# review：点读视频 → 朗读成绩单

```
点读视频 ──feeder read --draft──► 测量数据（storage/data/…）
    +      （一次录音 = 一份，        └─► spec 候选（…/<slug>.draft.txt）
教材原文     跨页只当标注）                │ 会话核对：定性 · 打分 · 写点评
.ref.txt                                  ▼
              storage/spec/english/review/<slug>.txt ──build.py──► <那天>.html
                                            （一天一份，当天每次录音是页内一节）
                                             + 目录页 + 趋势页
```

先读根 `CLAUDE.md`（发布策略）和 `src/generator/english/CLAUDE.md`
（**本栏目的口径全在那儿**：分工线、四维、分档、三条不能违反的）。
这个 skill 不带脚本 —— 机器该做的都在喂数据台里，同一个口径留两份实现早晚会漂。

```bash
F=../feeder/bin/feeder        # 没编过就先 cd ../feeder && make cli
```

## 流程

1. **确认读了哪几页、原文在不在。** `super8/L3` 的 **p63–p79 原文已经在库里**
   （`storage/data/…/pNN.ref.txt`），直接用。换课换书才要先
   `$F scan <教材截图…> --split --slug <书>/<课>`。
2. **跑测量 + 起草。** **颗粒度是一次录音** —— 一口气读了几页就是一份，
   `--ref` 按朗读顺序给几份，名字写区间：

   ```bash
   R=storage/data/english/review/super8/L3
   # 一页
   $F read 点读.mp4 --slug super8/L3/p70    --ref $R/p70.ref.txt --draft
   # 两页（同一段录音）
   $F read 点读.mp4 --slug super8/L3/p68-69 --ref $R/p68.ref.txt,$R/p69.ref.txt --draft
   ```

   **不切文件、不重跑。** 每页多少词、错几处、占哪段时间是从同一份对齐里派生的，
   跑完会打出来。**某一页「只对上 N%」就是 `--ref` 的页码或顺序给错了** ——
   回去改再跑，别在草稿上硬改（`[比对]` / `[卡壳]` 全是照错的基准算的）。
   名字和 `--ref` 的页对不上会被当场拒掉，不用担心配错。
3. 十几秒出结果：三份测量数据落 `storage/data/…`，一份 `.draft.txt` 落
   `storage/spec/…`。**`--ref` 别省** —— 没有它就没有逐字比对，草稿也就空了大半。
4. **核对草稿。** 机器填好的部分（文件头、`[比对]`、`[卡壳]`、`[磕巴]`）过一眼，
   `⟨⟩` 包着的是判断，见下一节。**带 `.draft.` 的文件 build 会跳过**，
   所以草稿放在那儿慢慢改，不会污染线上报告。
5. **改名 → 构建**：`mv p70.draft.txt p70.txt && make build`（0.15 秒）。
   打卡评价是网页不是打印单，**不用 `--pdf`**。
6. **自检**（见「自检」一节），过了直接 commit + push。

## 人必须拍板的四件事

草稿里 `⟨⟩` 包着的都是。**改完 grep 一遍 `⟨` 确认没漏**。

| 判断 | 依据 |
|---|---|
| `errors` | 逐条看 `[比对]`。**替换 / 漏读 / 读错音计错；多读的词和回读不计错**。所以条数不一定等于 errors —— 一条里含两处错、或判成「识别错不是读错」都会差 |
| `[评分]` 四维 + `score` | 准确度 30 / 流利度 30 / 断句语调 25 / 发音 15。**维度名一个字都不能改**（写错会静默丢掉那一条），草稿的注释里给了逐字模板 |
| `naep` | NAEP 2002 四级量表。**踩在门槛上算低的那一级** |
| 点评文字 | `[总评]` `[亮点]` `[三件事]` `[斜线]` `[尺子]` `[怎么来的]` |

拿不准的**别硬判**：`[比对]` 里把「实读」改成「识别成」，编号会出 `?` 而不是数字 ——
那是给「判不准该算谁的」用的，不是给「懒得判」用的。

`words` 机器数好了，一般不动；只有「划线范围和 `.ref.txt` 不一致」时才按实际朗读范围改。

`[分页]` 那张小表机器填好了（跨页才有），数字别动 —— 它是从同一份对齐派生的。
缩进那一句是判断：写「哪一页更吃力、为什么」。整块删掉也行，报告就不出这张表。

## `[尺子]` / `[怎么来的]` 的套话

三句尺子**顺序固定**：准确率 / WCPM / 断句语调。一句写不下就换行 + 多缩进一层
（少缩进一格，图和话会错位，WCPM 那张图底下印出准确率）。

```
[尺子]
    <准确率>% 落在「<档>」这一档 —— 比上一页（<上页>%）<往左/往右>挪了一截。
        <多少词错多少处；段落越短一处错占的百分点越多>
    <WCPM> 个正确词/分钟：<和上一页比>，压在**<年级><季><百分位>**线上。
        母语常模只当参照系，不是及格线。
    平均 <N> 个词一组，<和上一页比>。
```

分档 Fountas & Pinnell BAS 1 p.40：**≥98 独立 / 95–97 教学 / <95 偏难**。
WCPM 常模 Hasbrouck & Tindal 2017 Table 4，是**母语儿童**常模。
具体数值在 `src/generator/english/figures.py`（一手来源，别在别处复制一份）。

```
[怎么来的]
**准确率 X%**（读对 N / 划线共 M 词）。替换、漏读、读错音计错；插入的词和退回去重读只算不流利、不计错。上面的比对列了 K 条、计错 N 处 —— <哪条含几处>。
**每分钟正确词数 W**（WCPM）= 读对的词数 ÷ <时长> 秒 × 60。
**断句**取 <P> 次停顿里断在句子中间的那些，平均 <N> 个词一组。
<录音来路、阈值、比对基准>。**发音一项是从转写结果推断的**，不如亲耳听准。
```

## 自检

- **`[评分]` 四维之和 == `score`。** `make build` 现在会拦（对不上直接报错、
  维度名写错也报），但四个数分别给多少仍旧是人定的 —— 校验只保证加得平。
- `make build` 之后 **Read 生成的日页**（`dist/english/review/<YYYY-MM-DD>.html`），
  别凭 spec 想象。**报告是一天一份** —— 当天读了几次，就是页内几节；
  单次录音不再单独占一个 URL，目录页的行链的是日页的锚点。
- **核一眼停顿地图。** 没写 `[句末]` 时 `review.py` 从原文句号自动推
  （`auto_bounds()`），它**认不出段落切换和引号内的分句** —— 句末少几次，
  时间轴的三个计数就跟着偏。不对就手写 `[句末]`，**一行写完**（续行会被静默丢掉）。
  `[卡壳]` 同理。
- 趋势页和 `storage/result/english/review.csv` 会自动重算，扫一眼新那行对不对。
- **目录页每天头上那一条汇总**也会自动重算（当天几次、几页、多少词、合计准确率
  和 WCPM）。合计是「读对的总词数 ÷ 总词数」，不是取平均；**跨本的那天不出涨跌**
  —— 换书就换了一把尺子。看一眼数对不对，别去改代码里的口径。

## 已知坑

- **停顿数现在可以跨录音比了**（8/30 起）。阈值从「本底+8、下限−40」改成
  「说话声级−10」—— 旧口径按各自峰值归一，手机录的和视频抽的差了 20 dB 动态范围，
  阈值散在 −21.8 ~ −40，还有系统性偏差（撞下限的页少数了一半停顿）。
  所以 `[对比]` 那两行**不用再写「不可比」了**，照实写趋势。
  历史七份已重算回填，但**旧报告截图上的数字和现在不是一把尺子**，别拿来对。
- **`naep` 是人判的，不是从「几个词一停」换算的。** 新口径的数普遍比旧的小
  （现在 1.4–2.9，旧的 1.7–3.3），别看到 1.4 就自动往第 1 级挪 ——
  那一级说的是「一个词一个词往外蹦」，要听录音才判得准。
- **转写带置信度了**（`words.tsv` 第四列、`read.json` 的 `runs[].confidence`），
  整段中位数 0.82。但**它分不出「读错」和「转写没听准」** —— 拿人工定过的 p73-74
  验过：转写不准的 5 处全在 0.35 以上（0.37 / 0.40 / 0.60 / 0.66 / 0.80），
  真读错的反而有三处在下面（upon 0.19、torturing 0.23、off 0.25）。
  低置信度多半是**她这个词读得含混**（那往往正是真错），而专名被自信地认成
  另一个词置信度还很高。所以它只是「值得回去听一遍」的线索，**别拿它定性**。
- **`.ref.txt` 里冒出不是英文的词，先怀疑扫描认错，别急着写「课本印错」。**
  **根因是图太小**：这批教材图是微信压过的照片，828px 宽、正文字高才 17–19px，
  红线还压在字上，Vision 在这个分辨率上**丢细横笔画和 i 上那个点** ——
  `favor→lavor`（f 的横）、`Therefore→Theretore`（f 的上钩）、
  `thunderbolt→thunderboll`（t 的横）、`wisely→wiscly`（e 的横）、
  `aim→aum`（i 的点，i+m 粘成 um）、`little→hitle`。
  六处**全落在红线划中的范围里**，也就是全都进了比对基准。

  现在不用手工找了：`feeder scan` 把可疑词存进 `page.json` 的 `spellFlags`，
  还给每个词裁一张 `p<页>.suspect-<词>.png`（放大 6 倍、带上下文）；
  `read --draft` 在**头注最前面**把这几页的可疑词重报一遍，`[比对]` 里判成
  「原文可疑 · 建议不计错」。看到就去核那张 suspect 图 ——
  **机器给的首选建议常常是错的**（`lavor` 它猜 labor，实际是 favor；
  `hitle` 它猜 title，实际是 little），一定要自己看图。

  **是认错就改 `.ref.txt` 再把 read 重跑**，别在草稿里硬改 ——
  `[比对]` / `[卡壳]` / `[分页]` 全是照那份基准算的。
  真是课本印错的也有（p74 的 `cat` 该是 `eat`，图上确认过）。
  两种都不计错，但**报告上的归因不一样**，别把扫描的锅扣给课本。

  ⚠️ p65–p74 那批 `page.json` 是加 `spellFlags` 之前扫的，没有这份信息
  （它们的 spec 里已经逐条写明了）。要重读那几页得手工核。
- **课文读完之后那一串孤立的词，多半是在念生词表，不是「往下读课文」。**
  判法：词与词之间间隔明显、彼此不成句、在原文里连不成行 —— p70-72 的
  348.6–376.7 秒和 p73-74 的 249–288 秒念的是同一份。认出来要写进头注，因为
  ① 对齐算法会把这串词的末几个拉去顶原文结尾的词（desert / hermit 顶了 only / in），
  那几条比对是**假的**；② 这段算进时长、不算进正确词数，WCPM 偏保守，
  `[怎么来的]` 里要另给一个「只算课文那段」的数。
- **`[卡壳]` 抬头行的标签里不能有逗号** —— `,` `，` `、` 都是条目分隔符。
  现在 `make build` 会当场报是哪一条、为什么（以前只报
  `could not convert string to float`，看不出位置），feeder 起草时也会自己把
  标签里的逗号换成 `·`。手写的时候仍旧要躲开。
- **`[比对]` 的条数和 `errors` 不一定相等，这是正常的。** 报告上的编号是按
  「实读」条目顺着排的，所以编号最大值 ≠ errors：一条里含两处错就 errors 更多，
  有一条是回读 / 课本印错（写「实读」但不计错）就 errors 更少。
  **但差出来的那几条一定要在说明里点明**，否则读的人算不平账。
  判不准该算谁的写「识别成」—— 那种编号出 `?`，不占号。
- **换书就换了一把尺子。** 分数是给「这个孩子 + 这本书」的。跨本比只说明书难不难，
  看进步得同一本书跨天比 —— **这句话要写进报告**，别让人误读成孩子退步了。
- **发音是从转写反推的**（识别成什么词反推读成了什么音），写结论要留余地。
- **别提议把偏难的书换成听读 / 跟读。** 学校要求朗读，这条不可动。文本偏难（<95%）
  时建议要落在「偏难文本怎么朗读」上：先扫生词、分段、同一段读两遍。
- `grade:` 是**死字段**，`review.py` 从不读它。旧 spec 里有，新的别再写。
