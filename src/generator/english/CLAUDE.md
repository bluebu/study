# 英语 · 项目准则

学习小站的英语科。搬内容进来之前先读这份。

## 教学体系：对标美国本土

最高准则 —— 语法和句子分析一律对标美国本土权威体系（FLL、Rod & Staff、MCT、
Shurley English、Reed-Kellogg、Warriner's），**不教中国式五大句型**：

- 句子分析的地基是 **Subject + Predicate**
- be 动词句是 **主语 + 系动词 + 表语**（主系表），不是「主谓补」
- 术语跟着美国教材走，中文只当注释

面向的是小学中年级，文案里**不出现年级字样**。五条教学法：一关一概念、
先语感后规则（归纳式）、由整到细、低阅读压力、**绝不说教**
（不写「一定要记住」「必须」「要牢记」）。

## 栏目

```
review      打卡评价 —— 每天的朗读作业，一份能和下次比的成绩单   ← 已上线
ket         KET 核心词四线三格默写 —— 看中文写英文，25 个主题     ← 已上线
homework    每日打卡 —— 群公告 → A4 打印单                       ← 已上线
retell      复述故事 —— 老师白板的 Story Map → A4 关键词地图      ← 已上线
```

**栏目名不是目录名。** 代码在 `src/generator/english/<栏目>.py`，内容在
`storage/spec/english/<栏目>/`，测量数据在 `storage/data/english/<栏目>/` ——
两棵树靠栏目名对齐，取路径一律走 `paths.spec("english", "<栏目>")`（`lib/paths.py`），
**别用 `Path(__file__).parent` 往下拼**，代码和数据不在同一棵树上。
下面各节标题里的 `spec/…`、`data/…` 都是 `storage/` 下的相对路径。

一个栏目一个模块（`review.py` / `ket.py` / `homework.py` / `retell.py`），`build.py` 只做分发，
**每个栏目单独一层 try** —— 一个栏目的 spec 写错不该把另外两个带下水
（原先 review 和 ket 挤在一个函数里，review 那段提前 return 就会静默跳过 ket）。

老站 `../english/` 还在线上跑，上面这三个栏目的实现都在那儿，要参照就去翻。

## 词汇默写（spec/english/ket/）

CSV 是唯一输入，卷子全是产物。格式老站定稿过，别随手改：一页 30 词、
四线三格绿线红基线 11mm、合集分上下册（01–12 定稿不动）。
出卷、抽选、照片转 CSV 的完整流程在 `.claude/skills/ket/SKILL.md`。

答案对照版按 px 估算切页（`ket.py` 的 `ANS_PAGE_H`）—— 动了页眉页脚或字号，
**必须验一遍「HTML 里 .sheet 的个数 == PDF 页数」**，不等就是溢出、打出来夹空页。

## 打卡评价（spec + data/english/review/）

```
storage/data/english/review/
  <slug>.read.json         喂数据台（../../feeder）产出：声学 + 转写 + 逐字对齐
  <slug>.json              停顿声学，字段和老站 review/data/ 逐个对齐（**必需**）
  <slug>.ref.txt           红线划中的课文原文 —— 比对基准（可选，兜底算句末）
  <slug>.words.tsv         逐词时间戳（人核对用，生成器不读）
storage/spec/english/review/
  <slug>.txt               人的判断：哪几处算读错、四维分数、点评
storage/result/
  english/review.csv       算出来的指标，`write_result()` 每次全量重算覆盖
src/generator/english/
  review.py                生成器：单页报告 + index 汇总 + 趋势页
  figures.py               三把尺子 + 停顿地图 + 趋势曲线（常模数值是一手来源，别动）
```

**颗粒度是一次录音，不是一页。** 孩子一口气读了两页就是一份数据、一份 spec、
一份报告，名字写区间（`super8/L3/p68-69`），`--ref` 按朗读顺序给几份。
每页的小结（多少词、错几处、占哪段时间）从**同一份对齐**里派生，写进 `[分页]`
区块、报告里出一张小表 —— 只是标注，不影响任何指标的算法。

平时看的是**目录页上每天一条的汇总**（`day_summary`）：当天几次、几页、多少词、
合计准确率和 WCPM。合计是「读对的总词数 ÷ 总词数」，不是几份报告取平均。
**跨本不给涨跌** —— 换书就换了一把尺子，两把尺子量出来的数相减没有意义。

spec 不用从零写：`feeder read --draft` 会起草一份 `<slug>.draft.txt` 落到
`storage/spec/english/review/`，`[比对]` / `[卡壳]` / `[磕巴]` 和文件头都填好，
判断留 `⟨⟩`。人核对完改名成 `<slug>.txt` —— **带 `.draft.` 的文件生成器会跳过**
（`lib/spec.py` 的 `specs()`）。整条流程和判断口径见 `.claude/skills/review/SKILL.md`。

**slug 是「书 / 课 / 页」，斜杠就是目录**：`super8/L3/p68` →
`spec/…/super8/L3/p68.txt` + `data/…/super8/L3/p68.*` →
`dist/english/review/2026-08-27.html#super8-L3-p68`（**一天一个页面**，
当天每次录音是页内的一节）。
spec 里**没有任何字段指向数据文件**，全靠 `data/<slug>.<ext>` 拼路径 ——
名字错了 spec 和数据就配不上对，所以喂数据台在写盘前就校验名字形状。
slug 是反推出来的：`spec_path.relative_to(SPECS)` 去掉后缀。

四份文件要不要 push、哪些是核对完就扔的，见根目录 [DATA.md](../../DATA.md)。

`review.csv` 是**旁路不是必经**：单页报告仍直接吃 spec 全文 + 完整测量 JSON
（评语要逐字印在纸上、停顿地图要每次歇气的起止时刻），指标表装不下这些。
趋势页 `build_trend()` **故意从 CSV 读回来**，不吃内存里的 reports ——
那张表必须真能被别的工具消费，不然就是把内存字典换了个存法。

页码印在报告上的那个数**读的是 spec 的 `page:` 字段**，不是从 slug 解析的
（slug 里的 `p68` 只是名字的一部分）。`prev:` 可以只写页（`p67`），
同一课里会自动补成 `super8/L3/p67`。

### 一条分工线

```
机器算：时长、停顿、转写、逐词时间戳、逐字对齐候选、准确率、WCPM、几个词一停
人判断：哪处算读错、四维打分、点评文字、句末时刻
```

机器那半边现在还多分一道类：`read.json` 的每条差异带 `category` / `label` /
`suggest` / `why`（词尾、小词、原文印错、专名、转写乱段、自己改对……）。
**那是建议不是判决** —— `errors` 仍旧是人定的数。要在报告里用这几个字段就
**读了原样印**，规则和标签的唯一实现在 `../feeder` 的 `Output/DiffTriage.swift`，
这边一行都别重写（口径见根目录 [DATA.md](../../DATA.md)）。

spec 里**只写判断**。`words`（核对过的原文词数）和 `errors`（认定的计错数）
是仅有的两个数，其余全部算出来：

```
准确率   =（words − errors）÷ words
WCPM     = 读对词数 ÷ 时长 × 60
几个词一停 = words ÷ 停顿次数
```

老站那 7 份报告是手写 HTML，同一个数字在标题、四个数字、三把尺子、
「分数是怎么来的」里各写一遍 —— 改一处要改四处，改漏了没人发现。

### spec 怎么写

区块内一律是「**非缩进行 = 一个条目，缩进行 = 附属于上一条**」。
一句话写不下要换行，续行**再多缩进一层**：

```
[尺子]
    96.4% 落在「要带一带」这一档的中间——
        不过比上一页往右挪了一点。       ← 接上一句
    74 个正确词/分钟……                  ← 新的一句
```

不这么写，三把尺子的三句话会按行数错位一格 —— WCPM 那张图底下印出准确率的话，
看不出是 bug，只觉得读着别扭。

行内标记：`**粗**`，`*词*`（原文侧出 `<mark>` 绿、实读侧出 `<ins>` 红）。

区块（`[比对]` 之外都可省）：

| 区块 | 内容 |
|---|---|
| `[评分]` | `准确度=24/30 流利度=15/30 断句语调=13/25 发音=9/15` |
| `[总评]` | 抬头是一句话总评，缩进行是那一段说明 |
| `[句末]` | 原文真正的句末时刻，逗号分隔。**不写就按句号自动算** |
| `[卡壳]` | `26.0-28.2 = 卡 2.2 秒, …`，缩进行是时间轴下面那段话 |
| `[对比]` | 四行数值自动算，非缩进行给趋势词（`几个词一停 = 读得更成串`） |
| `[比对]` | `原文` / `实读` 成对，缩进行是说明。用 `识别成` 代替 `实读` → 编号出 `?` |
| `[磕巴]` | 每行一处回读，缩进行是说明 |
| `[亮点]` | 每段一行，缩进行是小字注 |
| `[三件事]` | `emoji 标题` + 缩进的说明 |
| `[斜线]` | 画好意群斜线的原文，每行一个意群 |
| `[尺子]` | 三句话，顺序固定：准确率 / WCPM / 断句语调 |
| `[怎么来的]` | 每段一行 |

录音和教材截图怎么变成 `data/` 里那几份，见根 `CLAUDE.md` 的「喂数据台」。

### 报告里的区块顺序（`review/one.html` 的 card 宏）

先给结论和要做的事，再给对比和明细：

```
分数卡（分数 + 尺子那行小字 + 总评 + 四维条）
✏️ 下次试试这三件事      ← 家长和孩子唯一真要执行的东西，紧跟在分数后面
📊 四个数字 · ↗️ 和上一次比
🌟 读得好的地方          ← 正面的排在明细之前
⏱ 停顿地图 · 📄 分页 · 🔍 逐字比对 · 🌀 读了两遍才接上
🪄 斜线 · 📍 三把尺子 · 📐 分数是怎么来的
```

原先「三件事」排在第 11 屏、「读得好的地方」跟在磕巴后面 —— 一份报告手机上
26 屏，真正要做的事得滚到底才看得到。**「亮点」和「磕巴」版式相同**
（`textblk` 宏），但位置各排各的，别再合回一个列表里连着出。

分数底下那行小字由 `score_ruler()` 出，说的就是上面第 1 条那句
「换书就换了一把尺子」—— 一天读了几次的话，整句只在头一节出现，
后面的节只留「上一次 N 分」。

### 口径（改之前先读 ../../english/review/README.md）

- **准确率**：替换、漏读、读错音**计错**；插入词和回读只算不流利、**不计错**。
  所以 `[比对]` 列出的条数不一定等于 `errors` —— p65 列了 6 处，其中一处是
  「读多了自己退回去重来」，不计错，errors 写 5
- **分档** Fountas & Pinnell BAS 1 p.40：≥98 独立 / 95–97 教学 / <95 偏难
- **WCPM 常模** Hasbrouck & Tindal 2017 Table 4，是**母语儿童**常模，
  只当参照系，不是及格线
- **断句语调** NAEP 2002 四级量表。「踩在 3 级门槛上」仍然算第 2 级
- **停顿** = 能量低于本底 +8 dB 且持续 ≥0.25 秒

### 四条不能违反的

1. **换书就换了一把尺子。** 分数是给「这个孩子 + 这本书」的，不是给孩子的。
   跨本比只能说明书难不难，要看进步得同一本书跨天比。**报告里要把这句话写出来**，
   别让人误读成孩子退步了
2. **发音是从转写反推的**（识别成什么词反推读成了什么音），不如亲耳听准，
   写结论要留余地。拿不准的直接标存疑（`识别成` + 编号 `?`），别硬判
3. **报告正文写给孩子和家长，不写给数据管道。** 机器为什么误判、我们怎么核的、
   哪几条「不计错」—— 一律留在 spec 的 `#` 注释里，**正文一个字都不提**。
   正文里不许出现 `.ref.txt`、「转写」、「机器判的」、「扫描认错」、「机器候选」
   这类词：家长读到文件名就把页面关了。

   **分界线是「这对孩子意味着什么」**，不是「提没提到机器」：

   - p67 第 4 处那样写是对的 —— 「这处没听清，具体读成了什么得你亲耳听 44–47 秒；
     计分时按错了 1 处算，如果其实读对了，准确率是 96.1%」。存疑、计了错、
     告诉家长怎么复核、说清这一分的去向，每一句都落在孩子身上
   - p73-74 原先那样写是错的 —— 「另有 10 处机器判的『读错』这次没算，都是转写
     自己乱了：三个专有名词、98–100 秒那一串 5 个词（比对里列了 4 条，标的是
     「识别成」）」。这是在跟自己对账，家长读完不知道该做什么
   踩过一次：p73-74 的总评有一大半在讲机器的毛病（「另有 10 处机器判的『读错』
   这次没算，都是转写自己乱了……是 `.ref.txt` 认岔了」），`[比对]` 列了 20 条、
   其中 6 条的结论是「不计错」，`[磕巴]` 的抬头直接叫「机器候选 13 处（不计错）」。
   一份成绩单三成篇幅在替机器解释，孩子要练的那 14 处反倒被埋了。

   落到具体几条：

   - **`[比对]` 里不留「核完确认不是她的错」的条目** —— 专有名词、转写整段乱掉的、
     扫描认错的、课本印错的，一律撤进 `#` 注释。撤干净之后 p70-72 是 27 条对
     `errors: 27`、p73-74 是 14 条对 14，家长能一条条数明白。
     **拿不准、但计了错的存疑条目要留**（`识别成` + 编号 `?`），那是准则第 2 条
   - **课本印错 / 扫描认错**这两种，她没被带跑其实是**亮点**，写进 `[亮点]`，
     别放在比对里当一条「错」讲
   - 区块抬头写人话（「读了两遍才接上的地方 · 4 处」），不写「机器候选（不计错）」
   - 录音里混进的非课文朗读（没划线的段落、生词表）只在 `[三件事]` 说一次，
     顺带点明它把 WCPM 和停顿两项拉低了 —— **别在四五个区块里各解释一遍**

4. **别提议把偏难的书换成听读 / 跟读。** 学校要求朗读，这一条不可动。
   文本偏难（<95%）时建议要落在「偏难文本怎么朗读」上 —— 先扫生词、分段、
   同一段读两遍（repeated reading）

## 每日打卡（spec/english/homework/）

群公告 → `storage/spec/english/homework/<YYYYMMDD>.txt` → 一张 A4。spec 格式和老站
`../../english/homework/specs/` 完全一致（那五份直接拿过来就能跑）。

```
[听] 听外教音频 | 120 分钟          ← [类别] 标题 | 右侧小标签
    今天实际听了 __ 分钟            ← 普通说明行；__ 出一条填空横线
[点读] 点读 · 超8 Lesson 3
    * 第 61–62 页 单词部分          ← * 圆点列表
[练] 单词抄写 | 每天 2 个
    + close to = 几乎，接近         ← + 单词表，每行带一个勾选框
```

`<<2>>` 出 2 个小方格（读 N 遍勾 N 个）。类别关键字定色条：
听/指 蓝、读/点 橙、词/写 绿、练/AI 紫、语/法 青。

### 整理公告的规矩（老站 skill 定的，照着来）

- **不增不删**：给的项一个不落，也不自己加
- **序号常乱**（同时冒出两个 5️⃣ 是常事）：按内容重排成连续序号，
  重复的合并、混在一条里的两件事拆开，**并在汇报时说明怎么改的**
- 一件事一张卡（「听音频 + 指读 2 遍」拆成两张）
- 标题短，细节下沉到 `*` 列表；数量 / 时长 / 遍数放 `|` 后面当小标签
- **给孩子留可填处**：时长写 `今天实际听了 __ 分钟`，读 N 遍写 `<<N>>`，
  抄 N 个词留 N 条横线
- 具体单词用 `+ word = 释义`，释义照抄公告
- 页码区间用 en dash（`68–69`），中英文之间留空格
- 公告末尾的「打卡模板」「多听外教音频」这类叮嘱**不进卡片**
- 重复昨天的作业：拷一份昨天的 spec，只改动的那几项，别从头写
- **公告有歧义先问**（页码写成 `3537`、单词数和列表数不符），别猜

排版目标是「**干净地放满一页**」：底部空太多就加大 `memo:` 行数，
快溢出到第二页就减备注行或精简说明行。**改完 Read PDF 自检**，别凭 HTML 想象。

## 复述故事（spec/english/retell/）

老师在白板上把整个故事拆成十几段，每段一串关键词、用箭头竖着串下来，
拍下来是十几张照片。翻着照片没法复述 —— 挪到一张 A4 上，一段一行，
眼睛一次扫完整个故事的走向。

照片先过喂数据台（`../../feeder/bin/feeder board 板*.jpg --slug <故事名>`），
它出关键词候选和核对图。**白板是手写，OCR 认不准是常态**，所以那份 `.draft.txt`
只是把「抄」变成「核」—— 关键词一个不删不加不改写这条铁律不因为有了机器就松。

分组按 **Plot Diagram** 的五个阶段走 —— 美国四年级正在学的那套：
Exposition → Rising Action → Climax → Falling Action → Resolution。
阶段名挂在左边当路标，段落归到对应阶段下面。孩子讲的时候知道自己讲到哪一段了，
而 CLIMAX 通常只有一段，一眼看出整本书的转折在哪儿。

```
[EXPOSITION] 铺垫 | 谁 · 在哪 · 出了什么事
king · just, hunting, rabbit, safe · hurt, food · cozy place
Fairy Truth, rabbit · rescue, test · kind, kinder people, friend · wish come true

[CLIMAX] 转折点 | 最转折的一下
tutor, escape, capture, Fairy Truth, monster, lion · wolf · snake · bull
```

一个 `[区块]` 是一个阶段（`[英文阶段名] 中文短名 | 这一段在干什么`），
区块内一行一段，**逗号分隔节点**；节点内部并列的词用 `·` 连着写
（`safe · hurt` 是一个节点，不是两个）。渲染时逗号变成箭头，段落编号跨阶段连续。

阶段数不限死五个，多一个少一个都照排 —— 归组本身就是解读。

### 四条

1. **只出英文，不配中文。** 配了中文，眼睛会先去看中文，复述就变成翻译了。
   生词（shepherdess / caretaker / unrewarded）留给她在故事里猜 ——
   这批词本来就是她这两周指读过的。中文只出现在阶段抬头上（"铺垫"、"越陷越深"），
   那是路标，不是词义
2. **关键词是老师给的，归组是解读。** 关键词一个不删不加不改写；
   哪几段算「铺垫」、哪一段是「转折点」是我们的判断，不是老师给的。
   改归组只动 spec 里的区块归属，**别动关键词本身**
3. **照抄板书，包括拼写错误**（`docter`、`wasn't die` 都是老师写的）。
   要改也是口头提一句，别在纸上改 —— 孩子对着的是老师给的那张图
4. **一段不能被分页切开**（`break-inside: avoid`），排不下就调行距，
   别让一段的关键词裂在两页上

### 排版上的两个坑

- 「词 + 它后面的箭头」要绑成一个不换行的 unit。不这么做，折行时箭头会落到
  下一行的行首（「→ kinder people」），读着像这行是从箭头开始的
- 行距要试出来：16 段、关键词 16.5px、段间 2.6mm 正好一页（八成半）。
  **单独跑这个栏目试**（`from retell import build_retell`），
  别用 `build.py --pdf` —— 那要顺带出 31 份 ket 卷，一轮两分钟起
